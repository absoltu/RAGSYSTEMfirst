# RAG System

Этот проект реализует простую Retrieval-Augmented Generation (RAG) систему на Python с использованием ChromaDB для векторного хранения и LM Studio для генерации ответов.

## Цели проекта

- Парсинг PDF-документов в удобный текст/markdown
- Разбиение текста на чанки с перекрытием
- Построение эмбеддингов для каждого чанка
- Сохранение чанков и эмбеддингов в векторную базу ChromaDB
- Построение терминального чата с опциональным RAG-контекстом
- Поддержка MMR-поиска для более разнообразных результатов

## Архитектура

Проект состоит из следующих основных частей:

- `converters/document_converter.py` — парсит PDF с помощью Docling и экспортирует документ в markdown/text/json
- `chunkers/chunker.py` — делит текст на чанки с заданным размером и перекрытием
- `embeddings/embedding_client.py` — получает эмбеддинги через LM Studio/OpenAI-compatible API
- `vectordb/chroma_client.py` — работает с ChromaDB, создаёт коллекции и добавляет документы
- `retrieval/search.py` — выполняет обычный и MMR-поиск в коллекции
- `rag/rag_system.py` — объединяет поиск, генерацию контекста и модельный интерфейс
- `rag/model_interface.py` — отправляет запросы к модели и получает ответы
- `rag/context_generator.py` — формирует текст контекста для модели
- `chat.py` — простой терминальный чат для вопросов и ответов

## Как создаётся векторная база

Основной процесс создания коллекции описан в `create_collection.py`.

1. **Разбиение PDF по частям**
   - `utils/pdf_splitter.py` делит исходный PDF на более мелкие файлы по `PDF_BATCH_PAGES`
   - Это помогает обрабатывать большие документы пакетно

2. **Конвертация PDF в текст/markdown**
   - `DocumentParser` из `converters/document_converter.py` использует Docling
   - Он может выполнять OCR и структурировать таблицы, если включено в конфиг
   - В файле `DocumentParser.convert()` результат экспортируется в `markdown`

3. **Очистка markdown**
   - `utils/markdown_cleaner.py` очищает лишнюю разметку и шаблоны
   - Это делает текст более пригодным для дальнейшей сегментации и поиска

4. **Сегментация на чанки**
   - `chunkers/chunker.py` создаёт чанки текста
   - Размер чанка и перекрытие задаются через конфиг: `DEFAULT_CHUNK_SIZE`, `DEFAULT_OVERLAP`
   - Если используется `token`-чанкер, он учитывает размер токенов через `TOKENIZER_MODEL`

5. **Сбор метаданных**
   - `utils/chunk_sectioning.py` добавляет информацию о секции и источнике
   - Это позволяет фильтровать результаты по разделу или файлу

6. **Генерация эмбеддингов**
   - `embeddings/embedding_client.py` вызывает `client.embeddings.create(...)`
   - Поддерживается пакетная обработка через `utils/token_batcher.py`

7. **Сохранение в ChromaDB**
   - `vectordb/chroma_client.py` создаёт коллекцию и вставляет чанки с эмбеддингами
   - Каждому документу/чанку сохраняются `source_file`, `section`, `chunk_index` и другие метаданные

После этого коллекция готова к поиску.

## Как осуществляется поиск

### Обычный поиск

Класс `retrieval/search.py::ChromaSearcher` делает следующее:

- получает эмбеддинг запроса
- выполняет `collection.query(...)` по ChromaDB
- извлекает документы, метаданные и расстояния
- вычисляет косинусное сходство для каждого результата
- сортирует результаты по релевантности

### MMR-поиск

Метод `search_with_mmr()` добавляет Maximal Marginal Relevance:

- получает расширенный набор кандидатов
- выбирает результаты, которые одновременно релевантны запросу и различаются друг от друга
- помогает уменьшить дублирование ответов и повысить разнообразие

## Работа RAG-чата

`chat.py` запускает простой терминальный интерфейс.

- Если `RAG_ENABLED = True`, то запрос проходит через `rag/rag_system.py`
- Если `RAG_ENABLED = False`, модель отвечает без контекста
- Контекст для модели формируется из лучших `CONTEXT_TOP_N` чанков
- Системный промпт задаётся в `config.py` через `SYSTEM_PROMPT`

В конфиге вы можете настроить:

- `RAG_ENABLED` — включить/отключить RAG
- `SEARCH_TYPE` — `def` или `mmr`
- `MMR_LAMBDA` — баланс релевантность/разнообразие
- `CONTEXT_TOP_N` — сколько чанков включить в контекст
- `CHAT_TEMPERATURE` — температура генерации
- `CHAT_MAX_TOKENS` — максимальное число токенов ответа
- `RAG_COLLECTION_NAME` — имя коллекции ChromaDB для поиска

## Пример запуска

### Создание коллекции

```bash
python create_collection.py
```

### Терминальный чат

```bash
python chat.py
```

### Тесты

Все тесты находятся в папке `tests/`:

```bash
python tests/test_rag_components.py
python tests/test_mmr_search.py
python tests/test_search.py
```

## Требования

- Python 3.11+ (или близкая версия)
- ChromaDB
- LM Studio на `http://localhost:1234`
- Документы в папке `documents/`

## Полезные заметки

- `create_collection.py` предназначен для офлайн-построения коллекции, он разбивает PDF, конвертирует каждую часть, строит эмбеддинги и вставляет их в Chroma
- `rag/rag_system.py` использует поиск, контекст и модельный интерфейс как отдельные слои
- `README_RAG.md` описывает архитектуру и запуск, а `chat.py` предоставляет быстрый CLI

Если хотите, могу добавить ещё разделы по настройке Docling или по отладке ChromaDB.
